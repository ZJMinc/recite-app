# 内容工作流（加卡 / 批量导入）

卡片的唯一数据源是 [`src/data/seed.ts`](../src/data/seed.ts)，章节树在
[`src/data/curriculum.ts`](../src/data/curriculum.ts)。改完刷新页面即可，`initDB()`
按 id 补齐缺失卡片，**不会覆盖已有学习进度**。

写卡原则（一张卡只考一个点、挖空只挖关键词、能编口诀就编）见
[README「内容怎么加」](../README.md#内容怎么加)。

## 一、一条命令的质量闸门

```sh
pnpm test          # = 内容校验 + 同步合并测试 + 刷题逻辑测试
```

只跑内容校验：

```sh
node scripts/validate-content.mjs
```

它会检查：

| 检查 | 拦下的问题 |
|---|---|
| id 唯一 | 复制粘贴出来的重复卡 |
| `chapterId` 存在、`subjectId` 与章节一致 | 刷题时组到错误章节 |
| **id 前缀与章节一致** | 不同章节撞用同一编号（人工编号必撞） |
| 题型合法、`importance` 在 1..5 | 脏数据 |
| 选择题：≥2 选项、无空选项、`answer` 不越界 | 判分永远错 |
| 判断题：`answer` 是布尔、`back` 与之一致 | 写了「正确」却是 `false` |
| 挖空卡：`{{ }}` 成对且非空 | 渲染穿帮 |
| 问答卡：`front`/`back` 非空 | 空白卡 |
| 题干完全重复 | 同题多份 |
| 章节是否「有卡片但 0 道客观题」 | 某章刷题整章空白 |

并输出题型 / 科目 / 章节分布，以及**客观题只有 1 道的章节**（组卷会很单薄）。

## 二、批量导入

适合一次补几十张（例如按章节整理好的一批题）。格式是 JSON 数组：

```json
[
  {
    "id": "p5-c3",
    "subjectId": "pedagogy",
    "chapterId": "p5",
    "kp": "课程类型的划分",
    "type": "choice",
    "front": "按课程内容的组织方式，课程可分为（　）。",
    "options": ["学科课程与活动课程", "必修课程与选修课程", "显性课程与隐性课程", "国家课程与地方课程"],
    "answer": 0,
    "back": "学科课程与活动课程",
    "analysis": "按内容组织方式分学科课程与活动课程；按实施要求分必修与选修；按呈现方式分显性与此隐性。",
    "importance": 4
  }
]
```

也可以包一层：`{ "cards": [ ... ] }`。

先 dry-run 看会写进去什么：

```sh
node scripts/import-content.mjs cards.json
```

确认无误再落盘：

```sh
node scripts/import-content.mjs cards.json --write
node scripts/validate-content.mjs
```

行为约定：

- **只追加，不覆盖**：id 与已有卡片重复会直接报错，不会悄悄改老数据
- 任一卡片校验失败 → **整批不写入**，退出码 1（避免半批数据进库）
- 题干与已有卡片重复只警告（不同章节确实可能有相似题干）
- 写入的字段顺序固定，便于 git diff

## 三、手工加卡

直接在 `src/data/seed.ts` 里追加对象即可，字段含义：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 唯一，建议「章节-序号」，如 `p5-c3` |
| `subjectId` | ✓ | 必须与章节所属科目一致 |
| `chapterId` | ✓ | 见 `curriculum.ts` |
| `kp` | ✓ | 知识点名称，卡片标题 |
| `type` | ✓ | `cloze` / `qa` / `choice` / `judge` |
| `front` | ✓* | 题干；挖空卡可留空 |
| `back` | ✓ | 答案；挖空卡用 `{{答案}}` 标记；判断题写「正确」或「错误」 |
| `options` / `answer` | 选择/判断 | 选择题 `answer` 是选项下标；判断题是布尔值 |
| `analysis` | 建议 | 解析 |
| `mnemonic` | 可选 | 口诀 |
| `confusables` | 可选 | 易混提醒 |
| `importance` | ✓ | 1–5，决定新卡顺序与组卷优先级 |
| `tags` | 可选 | 标签数组 |

## 五、容量与体积（已做按科目拆包）

卡片按科目拆在 `src/data/cards/<subject>.ts`，由 `src/data/seed.ts` 动态 `import()`。
Vite 为每个科目生成独立 chunk，主包不再随内容线性膨胀。

实测（628 张）：

| 产物 | 体积（gzip） |
|---|---|
| 主包 `index-*.js` | 476 KB（148 KB） |
| `pedagogy` chunk | 82 KB（23 KB） |
| `edupsy` chunk | 65 KB（19 KB） |
| `psychology` chunk | 45 KB（14 KB） |
| `law` chunk | 34 KB（10 KB） |
| `newcur` / `ethics` | 13 / 12 KB（各 4 KB） |

拆包前主包是 724 KB（226 KB gzip），拆后降到 476 KB。

**关键设计**：`initDB()` 先读一个种子版本标记（`meta.seedVersion` = 内置卡片总数），
已播种且数量未变就跳过，**老用户启动时完全不下载内容 chunk**；
只有首次安装或内容更新才加载。重置学习进度会同时清标记并重新播种。

按此结构扩到 1500 张时，主包基本不变，各科目 chunk 各自增长到 100–200 KB，
且只在需要时加载。

### 还没做的拆分

- 内容仍随版本发布，改一张卡也要重新部署（后续可走「内容上云」：seed → PocketBase，
  客户端按 `content_ver` 增量拉）
- 单科目内部未再细分（如教育学 208 张一个 chunk），到 500+ 时再考虑按章拆

## 六、内容一致性审计

`node scripts/audit-content.mjs`（或 `pnpm content:audit`）检查两类问题：

1. **近似重复题干**：换说法但问同一件事的卡片。
   精确重复由 `validate-content` 拦截，但「我国义务教育的年限是（　）。」
   与「我国义务教育的年限是（　）年。」这种只差一两个字的变体会漏过。
   脚本用字符二元组 Jaccard 相似度做全量两两比较，默认阈值 0.72。
2. **同一知识点散落多处**：同一 `kp` 出现在多张卡上，便于人工确认
   是「多角度出题」还是「重复表述」。

首次运行（1200 张）发现 7 对近似重复，全部是跨批次累积产生
（如义务教育年限、十项准则、第一首实施学制各被问了两遍）。
处理方式不是简单删除，而是把重复的那张**改写成相邻但不同的考点**，
避免学习进度中的卡片 id 失效，也保住了卡片总量。

复检结果：近似重复 0 对；115 组「同一知识点多张卡」经抽查属于
合理多角度（如「德育方法」下分别考概念、辨析、判断）。

这项检查暂未纳入 `pnpm test` 卡点 —— 近似重复不一定是错误，
属于需要人工判断的告警，纳入 CI 会误伤正常内容。
